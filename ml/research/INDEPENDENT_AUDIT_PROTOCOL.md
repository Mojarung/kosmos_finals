# Независимый повторный аудит модели — 26.09.2026

## Решение до запуска

Кандидат: `artifacts/next_optical/recipe.json` (`boost_learned`, S1+S2, порог 0,46). Выбран как последний поставляемый пакет по истории разработки, до нового расчёта метрик. Контроли: исходный S1-ансамбль сервиса, предыдущий `goal072_optical`, обязательный VH baseline. Отдельно проверяется принудительное отсутствие S2 у кандидата. Веса, нормализация, калибровка и пороги не меняются.

Пользователь — оператор, использующий вероятности для EL и приоритетов съёмки. Поэтому проверяем не только IoU, но ошибки вероятностей, пропуски воды, географические провалы, неопределённость, контракт растров и работу без оптики.

## Данные и независимость

- Все 105 ранее отложенных чипов: test_core 55, test_adjacent 35, Bolivia 15; исходные train/valid исключены. Чипы скачиваются из официального бакета с проверкой MD5 и сохранением manifest.
- Общая маска оценки: конечны оба канала S1 и ручная метка равна 0 или 1. Наличие S2 не меняет набор оцениваемых пикселей.
- Оптика допускается только по зафиксированному правилу пакета: календарная дата S2 не позже S1, разница до двух дней; проверяется сетка. Облака отдельно не замаскированы штатной QA-маской.
- Это независимый аудит кода/повторный inference из весов, **не новый слепой test**. Метрики всех трёх частей известны из прошлых исследований. Event CV использовалась для отбора кандидата. Bolivia географически исключена из train, но её предыдущие результаты тоже известны.
- Новый слепой результат потребует нового события с независимой разметкой, не использованного в разработке. Его нельзя получить переименованием старого test или новым bootstrap.

## Проверки и правила вывода

1. Зафиксировать commit, SHA256 моделей/рецептов/кода, входные списки и версии среды. Проверить отсутствие общих ID train/valid/test и пересечения событий; отсутствие общих ID не выдавать за пространственную независимость.
2. Получить свежие прогнозы, не использовать исследовательские prediction caches. Сохранить локальные прогнозы отдельно от сервисных данных. Общие неизменные радарные вычисления можно переиспользовать между рецептами при совпадении весов и нормализации.
3. Посчитать pooled IoU, Dice/F1, precision, recall, TP/FP/FN/TN, число валидных пикселей; по частям, событиям и чипам. Для вероятностей — Brier, ECE (15 равных интервалов), reliability; для неопределённости — AUROC ошибок на фиксированной выборке пикселей. Baseline не получает фиктивных вероятностных метрик.
4. Парные разности latest−previous и latest−service; описательный bootstrap по целым событиям для test_core, по чипам для одного события Bolivia с явной оговоркой о корреляции. Seed 260926, 2 000 повторов. Ноль внутри интервала означает отсутствие убедительного подтверждения преимущества.
5. Проверить p∈[0,1], конечность, маску при замороженном пороге, CRS/transform/shape/dtype/nodata на выходах пакетного CLI. Проверить S2 отсутствует/дата в будущем/частично невалидна, без удаления пикселей S1 из оценки. Отдельно сравнить CPU и основной вычислитель на одном заранее выбранном чипе (первый test_core).
6. Никакой настройки после результатов. Если кандидат не превосходит предыдущий устойчиво, не объявлять улучшение доказанным. Выбор для внедрения учитывать вместе с дополнительными зависимостями, доступностью оптики и временем вычисления. Сервис автоматически не переключается по одному красивому числу.

Требования: постановка, с. 7–11 и 21–22; критерии 1–12, связь с 13–14. Дополнительные источники разрешены, рабочий S1-only обязателен. Минимального IoU в ТЗ нет; научные результаты не являются порогом оценки.
