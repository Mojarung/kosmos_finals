# Ресерч после обновления ML до cae7833

Это исходный обзор до следующей серии обучения. Продолжение: [завершённые
эксперименты L2A, TerraMind и Kuro Siwo](SERVICE_ITERATION_RESULTS.md).

Исходники подтянуты fast-forward, новые веса получены через LFS и проверены.
Здесь разделены опубликованные результаты коллеги, новый законченный эксперимент
и гипотезы следующих прогонов. Поставляемые модели не заменялись.

## Что изменилось

Новый `context_model` использует пять фолдовых ResNet34 с оптикой; радарный режим —
пять ResNet34 и пять EfficientNet-B4. Входы: S1 события, статистики прежних RTC того
же трека, HAND/DEM/уклон, JRC, WorldCover, опционально S2 L2A.

| Опубликованный режим | test_core | test_adjacent | Bolivia |
|---|---:|---:|---:|
| Наш S1+S2Hand `next_optical` | 0,84938 | 0,83813 | 0,83735 |
| Новый радар с контекстом | 0,68944 | 0,71859 | 0,70645 |
| Новый контекст + S2 L2A | 0,82058 | 0,81544 | 0,81638 |

Это закоммиченные числа, не новый тест. S2Hand L1C и L2A с облачной маской — разные
входы: разность не измеряет чистый эффект архитектуры. Для новых рамок сервис
использует контекст, для известных чипов — `next_optical`.

Новый 5-fold OOF исключает соседние чипы, сохраняя знакомые события; наша 3-fold CV
исключает целые события. Их 0,76024 и 0,78410 нельзя сравнивать как одну метрику.
Контекстные сети нельзя включать в прежние event-CV-смеси: они видели часть внешних
событий. Нужны одинаковые фолды и заново полученные OOF-прогнозы.

Уточнено противоречие в `fresh/PROTOCOL.md`: WorldCover 2021 не был доступен для
событий 2016–2019, JRCWaterHand использует также 2018 год. В `fresh/RESULTS.md` это
уже отмечено. Это не доказывает обучение по тестовым меткам, но исключает заявление
о строго исторической доступности всех входов.
[Описание продуктов ESA](https://esa-worldcover.org/en/data-access).

## Завершённый эксперимент

Проверены расширенные оптические окрестности LightGBM: три обученные модели,
четыре доли в ансамбле, все три event-фолда. Контроль повторил counts каждого чипа.
**Гипотеза не прошла:** event IoU 0,784098 у контроля против 0,783104 у лучшей новой
смеси; pooled IoU 0,821956 → 0,819870. Первые два фолда немного улучшились, третий
ухудшился сильнее. Полная замена оптической ветки дала 0,770646.
[Протокол](CONTEXT_FOLLOWUP_PROTOCOL.md), [результаты](SPATIAL_BOOST_RESULTS.md).
Test не запускался. Это скрининг прежнего ансамбля, не переоценка `context_model`.

## Открытые данные: проверены первоисточники и файлы

### Kuro Siwo — кандидат для радарного предобучения

[Репозиторий авторов](https://github.com/Orion-AI-Lab/KuroSiwo),
[WebDataset](https://huggingface.co/datasets/orion-ai-lab/Kuro-Siwo-Webdataset):
43 события, снимок события и два прежних S1, DEM; CC BY 4.0. Доступны также
FloodViT/SNUNet и GeoTIFF. Для нашей water-IoU объединяются permanent water и flood.
Чужие дообученные веса требуют проверки обучающих событий до использования в CV.

Скачан префикс 8 MiB первого train-shard, разобран образец 224×224: Togo / EMSR470,
50 176 валидных пикселей, 879 воды. У этого образца нет пересечения с нашими 446
чипами с географическим буфером. Это не проверка независимости всей базы.

GRD хранится как **линейная sigma0**: официальный SNAP XML отключает
outputImageScaleInDb. Адаптер делает **10 log10(power)** и сохраняет valid-mask.
Чтение этих массивов как dB испортило бы обучение. Один shard — около 10,9 GB,
поэтому использован HTTP Range, без загрузки целого архива.

### WorldFloods v2 — кандидат для оптики

[Проект авторов](https://github.com/spaceml-org/ml4floods),
[набор](https://huggingface.co/datasets/isp-uv-es/WorldFloodsv2). Лицензия CC BY-NC 4.0:
исследовательское использование и коммерческая поставка весов — разные случаи.

Скачаны метаданные **475 train-сцен**. Проверка против всех 446 наших чипов с буфером
0,02° исключила пять: одну Nigeria, три Spain, одну Somalia. **470 проходят только
пространственный скрининг**; остаются проверка общих событий, дат и разметки.
Растры WorldFloods не скачивались, обучения на внешних данных не было.

GT имеет два канала: clear/cloud и land/water. Автоматический HF imagefolder viewer
показывает классы папок и не подходит как загрузчик сегментационной задачи.
Метаданные содержат footprint, CRS, дату S2 и EMS-код для фильтра до обучения.

### FloodsNet и OMBRIA

[FloodsNet WorldFloods/USGS/Sen1Floods11](https://zenodo.org/records/8298840) уже
включает наш датасет: добавлять его целиком или использовать чужие веса без проверки
совпадений нельзя. Полезны отфильтрованные внешние события.
[OMBRIA](https://github.com/geodrak/OMBRIA) содержит S1/S2 до и после событий и маски
EMS; подходит для временных архитектур после аналогичной проверки географии и дат.

Проверки: [образцы](EXTERNAL_DATA_PROBE.json), [WorldFloods train](WORLDFLOODS_INVENTORY.json).
Записаны HF-ревизии, URL, контрольные суммы и `training_admission: false`.

## Приоритет следующих экспериментов

1. **Бустинг на сервисных L2A.** Обучить HGB/LightGBM/CatBoost на 12 L2A-полосах
   с SCL-маской и радаром, на тех же 332 чипах/пространственных фолдах, что контекст.
   Смешивать только совместимые OOF. Это прямой способ проверить перенос преимущества
   деревьев на новые рамки. Подстановка L2A в 13-полосный L1C-рецепт без переобучения неверна.
2. **Отдельные ветви текущего и прежнего S1.** Общий encoder, разности и взаимодействия
   на нескольких масштабах; рельеф отдельно. Добавить число наблюдений, возраст
   последнего снимка и разброс истории: сейчас `pre_valid` бинарный. Проверить
   group dropout и полностью отсутствующую историю на development. Kuro Siwo подходит
   для предобучения этой схемы.
3. **TerraMind tiny/base.** В [IBM TerraMind](https://github.com/IBM/terramind) есть
   [конфигурация Sen1Floods11](https://github.com/IBM/terramind/blob/main/configs/terramind_v1_base_sen1floods11.yaml):
   разные нормировки GRD/RTC и L1C/L2A, Dice, AdamW 2e-5, размороженный backbone.
   Начать с tiny и одного фиксированного development-фолда для проверки памяти/скорости,
   затем все фолды. Авторы отмечают проблему BatchNorm UNetDecoder на MPS и предлагают
   FCN/исправленную TerraTorch. Нужны общие pretrained-веса, не Sen1Floods11-finetuned
   checkpoint, видевший наши внешние события.
4. **Внешнее предобучение, затем наш train.** Отфильтрованные события Kuro Siwo /
   WorldFloods, одинаковая цель и единицы; затем смешанные батчи с Sen1Floods11.
   Контроль без внешних данных обязателен, иначе эффект объёма и домена не разделить.
5. **Оценка в точном режиме сервиса и ускорение.** Context test использует TTA=8,
   `run_frame` по умолчанию TTA=2 и tiled inference. На development измерить именно
   сервисные входы/тайлинг/TTA, затем калибровать. После этого дистиллировать ансамбль
   из 5–10 сетей в одну и сравнить IoU, калибровку, задержку и память.

[Исследование TerraMind на FloodsNet](https://arxiv.org/abs/2512.02055) сравнивает
base/large и frozen/unfrozen: base-unfrozen дал лучший баланс, U-Net сохранил
преимущество по recall. Более крупная архитектура не гарантирует лучший результат,
а чужой mIoU нельзя напрямую сравнивать с нашим water-IoU.

## Воспроизведение проверок данных

```bash
uv sync --frozen --group research --group dev
uv run python scripts/probe_external_data.py
uv run python scripts/inventory_worldfloods.py
uv run python -m pytest tests/test_external_data.py tests/test_spatial_boost.py -q
```

Каталоги и образцы в `data/external_catalogs/` игнорируются Git; отчёты, адаптеры,
тесты и команды сохраняются в проекте. Готовые модели этой итерацией не заменены.

Проверка: 86 тестов прошли; SHA256 всех 15 новых контекстных checkpoint совпали с
recipe; `git lfs fsck` и `git diff --check` прошли. На контрольном обучающем чипе
первые 47 признаков, индексы сэмплирования и метки нового эксперимента побитово
совпали с прежним LightGBM. Все экспериментальные процессы завершены.
