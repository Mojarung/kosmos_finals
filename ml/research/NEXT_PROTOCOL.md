# Следующая серия S1+S2

Контроль заморожен: `artifacts/goal072_optical/recipe.json`, test_core 0,848688.
Новые test-прогнозы получаются только после фиксации итогового рецепта.
Все пять направлений проверяются; включение в поставляемую модель требует
подтверждения на development-данных. Неудачные варианты также сохраняются.

1. HGB: до 2,03 млн train-пикселей, 1200 итераций, lr 0,03; отдельно hard-negative
   sampling с pilot-моделью, обученной только на train соответствующего фолда.
2. LightGBM и CatBoost на той же выборке. Early stopping по отдельным целым
   validation-чипам, не по случайным пикселям обучающих чипов.
3. Завершение SAR ResNet50 и U-Net/MiT-B2; сравнение на validation, затем
   event CV перспективного радарного варианта с сохранёнными контролями.
   В CV проходит лучшая радарная смесь, только если её гибрид с прежней
   оптикой превосходит контроль на исходной validation. Проверяются сочетания
   с old, hgb_large и all_learned; радарные CV-модели получают 30 эпох/2 crops.
   После обучения тех же CV-моделей без дополнительных train-прогонов
   проверяется сетка весов нового радара 0,25 / 0,5 / 1,0 для этих трёх смесей.
4. Небольшая S2 U-Net/ResNet18 по шести спектральным полосам; нормализация
   только по train, маска допустимости/политика дат прежние. Проверяется смесь
   с бустингом и контроль отдельно по областям с оптикой и без неё.
5. Адаптивное смешивание по вероятностям и качеству входов. Модель смешивания
   не использует координаты/ID события. Для её обучения нужны прогнозы на
   отложенных для соответствующей базовой модели чипах; оценка — на внешних
   целиком отложенных событиях. Нельзя оценивать метамодель на строках её fit.
   Дополнительно проверяется отдельная isotonic-калибровка по наличию S2:
   old/boost/all смеси; обе ветки fit только на inner validation, общий порог
   выбирается там же. Признак наличия S2 определяется входами и датами.

Исходные train=252/valid=89 и `research/cv_plan.json` сохраняются. Тестовые
test_core/test_adjacent/Bolivia исключены из обучения и подбора. S2 дата не
позже S1, максимум два дня раньше; отсутствующая S2 не исключает пиксели
из оценки. На финальном сравнении отдельно публикуются S1+S2 и S1 fallback.

Первичный критерий сравнения — средний IoU по отложенным событиям CV;
дополнительно pooled IoU, Brier, результат исходной validation, время CPU.
К финальному выбору допускаются варианты с исходной validation IoU не ниже
0,852746 (контроль 0,854746 минус 0,002, как допуск предыдущего отбора).
Среди них выбирается максимум event-CV IoU, при равенстве — меньший Brier.
Сам контроль включён в выбор: ухудшение не требует замены рабочей модели.
При конфликте показателей прежний контроль остаётся доступным отдельно.
Старый test уже известен: новый прогон не объявляется первым слепым тестом.
