# Локальные ML-итерации: протокол

Зафиксирован 25.09.2026 до получения результатов абляций. Только ML.

Исходные `artifacts/model`, `artifacts/evaluation` и `artifacts/split.json` сохраняются как v1. Новые результаты лежат в игнорируемой папке `runs/cv`, конфигурации — в `configs/cv`, полный список чипов — в `research/cv_plan.json`.

**Разделение.** Development = исходные train+valid (341 чип). Три внешних fold содержат целые события. События распределены жадно по числу чипов, без просмотра меток/качества: большее событие первым, при равенстве алфавит, наименее заполненный fold первым. Исходные test_core, test_adjacent и Bolivia не участвуют.

| Fold | Внешняя оценка по событиям | Train | Внутренняя validation | Внешняя оценка, чипов |
|---|---|---:|---:|---:|
| 0 | Mekong, Nigeria, Spain, USA | 165 | 59 | 117 |
| 1 | India, Pakistan, Sri-Lanka | 172 | 60 | 109 |
| 2 | Ghana, Paraguay, Somalia | 167 | 59 | 115 |

Внутри каждого fold используются исходные train/valid только оставшихся событий. Только train определяет нормализацию, веса и выборку кропов. Внутренняя validation выбирает checkpoint по pooled IoU при p=0,5, Platt-калибровку и порог. Внешние события используются для сравнения конфигураций. Это development CV, а не новая слепая итоговая проверка. Внутренняя validation может содержать соседей train, но внешние события целиком исключены из обоих наборов.

**Первая серия.** Seed 0, 30 эпох, batch 8, 2 кропа на чип за эпоху, проверка каждые 2 эпохи. Все сети стартуют с ImageNet; ранее обученные flood-веса не используются. Пять вариантов: контроль; половина кропов с балансировкой по площади воды; окно 384 начиная с эпохи 21; BCE+0,5 Lovász; sampler вместе с окном 384. На стадии 384 batch=4. Длительность и число шагов сохраняются: больший контекст имеет больший вычислительный бюджет, поэтому это сравнение практических конфигураций, а не утверждение о равных FLOPs.

Sampler выбирает половину кропов прежним равномерным способом, половину из непустых диапазонов доли воды [0], (0,1%], (1%,10%], (10%,50%], (50%,100%]. Для второй половины требуется хотя бы 50% валидных пикселей. Все метки и кандидаты берутся исключительно из train конкретного fold. Размеры пулов сохраняются в `train_summary.json`.

**Выбор.** Основной критерий — среднее IoU по всем десяти событиям, вторичные — pooled IoU, precision/recall, Brier, ECE и стоимость инференса. Сравнивать только одинаковые завершённые fold. После скрининга подтвердить перспективные изменения вторым seed; смеси и TTA отдельно калибруются на внутренней validation. Малое преимущество одного seed не считать устойчивым улучшением.

**Воспроизведение на Mac.** Команды из `ml/`; для Metal нужен доступ процесса к GPU. По умолчанию существующий CLI inference по-прежнему выбирает CUDA либо CPU. Выбор MPS явный.

```bash
uv sync
uv run floodvalue download
uv run python -m floodvalue.cv plan --out research/cv_plan.json
FLOODVALUE_DEVICE=mps FLOODVALUE_EVAL_BATCH=4 \
  uv run python scripts/run_cv_sweep.py \
  --configs control balanced context lovasz balanced_context --seeds 0
uv run python -m floodvalue.cv summarize \
  --root runs/cv --out runs/cv/summary.json
```

На CUDA убрать `FLOODVALUE_DEVICE=mps`. Для CUDA с поддержкой BF16 применяется BF16, иначе FP16 с GradScaler. Результаты на разном оборудовании могут численно различаться; сравнительные серии следует выполнять в одной среде.

В каждом fold сохраняются веса, нормализация, конфиг, списки чипов, история, прогнозы внутренней и внешней частей, baseline, калибровка и метрики. Завершённые совпадающие конфигурации пропускаются при повторном запуске; несовпадение конфигурации или плана останавливает запуск.

Для проверки смеси без переобучения:

```bash
uv run python -m floodvalue.cv_blend \
  --runs runs/cv/cv_r34_control/seed0/fold0 runs/cv/cv_r34_balanced/seed0/fold0 \
  --weights 0.5 0.5 --space logits --out runs/blends/control_balanced_fold0.json
```

Для TTA четыре поворота, с восстановлением ориентации до усреднения:

```bash
FLOODVALUE_DEVICE=mps uv run python -m floodvalue.cv_tta \
  --run runs/cv/cv_r34_control/seed0/fold0 \
  --out runs/cv/cv_r34_control_rot4/seed0/fold0
```

TTA использует identity-прогноз из кэша и делает три дополнительных прохода. Прогнозы остаются на исходной сетке, nodata не становится обучающей меткой. Разброс преобразований не подменяет независимость моделей ансамбля.

## Дополнительные проверки на сохранённых прогнозах

`python -m floodvalue.cv_calibration --run runs/cv/cv_r34_control/seed0/fold0 --out runs/calibration/control_fold0.json` сравнивает исходную sigmoid, temperature scaling и isotonic. Все параметры и пороги подбираются только на внутренней validation; внешние события оцениваются после подгонки. Platt уже записан в исходном `cv_result.json`. Для итогов Brier взвешивается по числу валидных пикселей. `weighted_fold_ece` — средневзвешенный ECE фолдов, а не ECE объединённого массива.

Смеси оцениваются с фиксированными равными весами, без поиска весов на внешних событиях. Выбор самой пары моделей по CV остаётся настройкой на development. Второй seed проверяет чувствительность к инициализации, но не заменяет независимый новый набор событий.

Первая серия сокращена до 30 эпох × 2 кропа на чип. Исходные опубликованные веса обучались 60 эпох × 4 кропа и объединяют пять seed. Поэтому CV-числа этой серии нельзя напрямую сравнивать с опубликованными 0,697 на test_core или 0,655 на Bolivia и объявлять выигрыш над финальным ансамблем v1. В контролируемых сравнениях внутри серии отличаются только явно заданные настройки.

**Адаптивное продолжение.** После завершения control, balanced и lovasz на всех трёх fold seed 0 их средние IoU по событиям составили 0,5406, 0,5620 и 0,5704. На основании этих development-результатов добавлен шестой вариант `balanced_lovasz`: совместить sampler и BCE+Lovász, сохранив остальные настройки. Это последующая гипотеза, не часть заранее зафиксированной пятёрки. После шести вариантов контроль и лучший по среднему IoU кандидат повторяются с seed 1; имя кандидата и рейтинг seed 0 записываются до запуска seed 1 в `runs/cv/confirmation_selection.json`.

До получения результатов seed 1 также назначены симметричные проверки контроля и выбранного кандидата: rotation TTA для обоих seed на всех fold; смесь seed 0/1 с равными весами отдельно без TTA и с TTA; isotonic на seed 1. Каждый вариант заново калибруется на своей внутренней validation. Для сравнения обучения сопоставлять одинаковое число моделей и преобразований.

После положительных результатов isotonic на одиночных моделях выполнена дополнительная проверка этой калибровки на ансамблях двух seed — симметрично для контроля и Lovász, с TTA и без. Команда `floodvalue.cv_blend` принимает `--calibration isotonic`; по умолчанию сохраняется прежний Platt. Итоговые результаты, включая отрицательное подтверждение одиночного Lovász, — в [CV_RESULTS.md](CV_RESULTS.md).
