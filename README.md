# FloodValue — оперативный атлас паводка

Рабочее место дежурного аналитика инфраструктурного оператора. По снимку Sentinel‑1 сервис показывает воду и неопределённость модели, оценивает риск для десяти объектов, а затем собирает заказ дополнительной съёмки под бюджет и срок. Руководитель получает сравнение стратегий A/B/C и один ZIP с картами, таблицами, параметрами и происхождением данных.

Продукт следует ходу решения **наблюдение → приоритет объектов → закупка → проверка качества и экспорт**. На 3D карте можно выделить любой прямоугольный регион. Расчёт выполняется там, где загружен Sentinel‑1; вне покрытия интерфейс прямо сообщает об отсутствии данных.

Текущая [оценка готовности по критериям и план работ](docs/08-status.md) обновляется вместе с изменениями сервиса. [Карта документов](docs/README.md) ведёт к исходной постановке и подробному разбору.

## Запуск

Нужны Podman Compose или Docker Compose. Для показа три подготовленных сцены и выходы настоящей модели уже включены в репозиторий, поэтому обучение и GPU при запуске не нужны.

```bash
podman compose up --build
# или docker compose up --build
```

Интерфейс: <http://localhost:18080>. API: <http://localhost:18000/docs>. Порты настраиваются переменными `WEB_PORT` и `API_PORT`. На macOS, если Podman VM не пробрасывает порты, можно запустить `python3 scripts/podman_tunnel.py` в отдельном терминале.

Локальная разработка:

```bash
uv sync --project backend --extra demo --extra test
backend/.venv/bin/uvicorn app.main:app --app-dir backend --reload
cd frontend && npm ci && npm run dev
```

## Что реально считает сервис

| Шаг | Источник | Результат |
|---|---|---|
| Вода | VV/VH Sentinel‑1, 5 моделей U‑Net ResNet34, калибровка Platt | p, маска при p ≥ 0,41, разброс ансамбля |
| Сравнение | VH < −23,6 dB; ручная метка только для диагностики | IoU/F1/precision/recall основного метода и baseline на общей валидной области |
| Риск | p из сетки 3×3 вокруг точки, учебные V и q из кейса | EL = p × V × q для каждого из 10 объектов |
| Закупка | зоны от 1 км², бюджет, дедлайн, обязательный объект | точный выбор корзины C, сравнение с A и широкой B |
| Цена | формула постановления №840 с выбранной редакцией коэффициентов | сценарный тариф 788,64 ₽/км², скидка по общей площади корзины |

Модель и baseline взяты из [ML-пакета этого проекта](ml/README.md). Веса ансамбля лежат в Git LFS. Метрики независимого `test_core` (55 чипов, 11,56 млн валидных пикселей): IoU **0,519 → 0,697**; для отдельного события Bolivia: **0,535 → 0,655**. Это оценка качества карты, а не оценка предотвращённого ущерба. На отдельной сцене результат может быть хуже: её показатели всегда показаны в разделе «Качество».

Сумма EL — модельная экспозиция учебного портфеля. «Охваченный EL» означает риск объектов, для которых планируется дополнительное наблюдение; он **не равен физически предотвращённому ущербу**. Разница стоимости B и C — экономия бюджета на данных при заданном тарифе, а не доказанный экономический эффект в мире. Новая съёмка через 6 часов — сценарное допущение. Постоянная вода не отделяется от паводковой. Точки объектов учебные; их координаты и V/q не являются реальным реестром Нигерии, Ганы или Камбоджи.

## Сцены и работа в интерфейсе

Три демонстрационные сцены [Sen1Floods11 v1.1](https://github.com/cloudtostreet/Sen1Floods11): Nigeria_812045 (21.09.2018), Ghana_313799 (18.09.2018), Mekong_333434 (05.08.2018). Каждый GeoTIFF прошёл замороженный inference без дообучения. Стартовый чип — Нигерия. По всем сценам можно:

1. Переключать радар, маску, p, неопределённость, пороговый baseline и ручную метку. Ручная метка показана как контроль, а не источник рабочего прогноза.
2. Двумя кликами выбрать произвольную область. Площадь воды, диагностика, объекты и план пересчитываются для неё. Если область лишь частично покрыта S1, площадь покрытия показана отдельно.
3. Выбрать объект на карте или в списке, посмотреть p, неопределённость, V/q и EL, закрепить его в плане.
4. Изменить бюджет, срок и цель плана. Сервис пересчитает стоимость с объёмной скидкой, объяснит недостижимость обязательного объекта, сравнит A/B/C и экспортирует решение.
5. Переключить светлую и тёмную темы; выбор сохраняется в браузере.

ZIP содержит `flood_probability.tif`, `flood_mask.tif`, `flood_uncertainty.tif`, `baseline_mask.tif`, `assets.csv`, `asset_loss.csv` (все 10 объектов, признак `in_region`), `candidate_orders.geojson`, `procurement_plan.csv`, `strategy_comparison.csv`, `metrics.csv`, манифесты и входные параметры. Все слои относятся к одному выбранному чипу; таблица качества независимой выборки прилагается отдельно.

## Воспроизведение данных

Компактные выходы модели лежат в `data/demo`. Исходные GeoTIFF и промежуточный inference намеренно не включены в Git. Для полного пересоздания скачайте три пары `S1Hand`/`LabelHand` из официального бакета `sen1floods11/v1.1` в `data/source`, затем:

```bash
git lfs pull
uv sync --project ml
uv sync --project backend --extra demo
for chip in Nigeria_812045 Ghana_313799 Mekong_333434; do
  ml/.venv/bin/floodvalue infer --s1 "data/source/${chip}_S1Hand.tif" --out "data/inference/${chip}"
done
backend/.venv/bin/python scripts/prepare_demo.py
```

`scripts/prepare_demo.py` сверяет размер, CRS и сетку растра, фиксирует SHA‑256 источника и выходов, строит слои для карты и независимый от ручной метки учебный портфель. Идентификаторы и характеристики десяти объектов фиксированы для каждого чипа; p берётся из модели. Метрики по `test_core` и Bolivia копируются из [отчёта ML](ml/REPORT.md).

## Проверки и структура

```bash
backend/.venv/bin/pytest backend/tests -q
cd frontend && npm run build
```

- `backend/app` — FastAPI, анализ региона, риск, планирование, экспорт.
- `frontend/src` — Vue и 3D MapLibre; рабочий интерфейс вдохновлён пространственной компоновкой [krasnoyarsk_kosmos](https://github.com/Mojarung/krasnoyarsk_kosmos), с другой палитрой и сценариями кейса.
- `ml` — исходный пакет модели, веса, протокол split и независимая оценка.
- `data/demo` — подготовленные реальные выходы модели для трёх сцен.
- `scripts` — сборка демо-данных и локальный туннель Podman.
- `docs/source` — постановка и критерии; `docs` — подробный разбор и [продуктовый сценарий](docs/product.md).

Kafka, Redis и внешняя LLM здесь не нужны: анализ трёх чипов и перебор корзин укладываются в обычные запросы. Присланный ключ никуда не записывался и не используется.
