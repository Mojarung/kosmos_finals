# FloodValue — оперативный атлас паводка

Рабочее место дежурного аналитика инфраструктурного оператора. По снимку Sentinel‑1 сервис показывает воду и неопределённость модели, оценивает риск для десяти объектов, а затем собирает заказ дополнительной съёмки под бюджет и срок. Руководитель получает сравнение стратегий A/B/C и один ZIP с картами, таблицами, параметрами и происхождением данных.

Продукт следует ходу решения **наблюдение → приоритет объектов → закупка → проверка качества и экспорт**. На 3D карте можно выбрать область в любом месте Земли между 85° ю. ш. и 85° с. ш. Сервис ищет доступные Sentinel‑1 RTC VV/VH, объединяет соседние кадры одного прохода, запускает замороженный ансамбль и привязывает решение к дате наблюдения. Одна рамка обрабатывается до 300 км²; для более крупной территории нужно выбирать участки. Если пиксели невалидны, доля покрытия показана отдельно.

Текущая [оценка готовности по критериям и план работ](docs/08-status.md) обновляется вместе с изменениями сервиса. [Карта документов](docs/README.md) ведёт к исходной постановке и подробному разбору.

## Запуск

Нужны Podman Compose или Docker Compose и доступ к Microsoft Planetary Computer для нового региона. Три подготовленных сцены включены в репозиторий и доступны офлайн. Ещё 446 официальных чипов Sen1Floods11 можно выбрать в панели «Другой снимок»: сервис скачает S1 и ручную метку, запустит ту же замороженную модель и добавит результат на карту. Новые снимки обрабатываются в контейнере на CPU весами из Git LFS; обучение и GPU при запуске не нужны. Повторное открытие использует постоянные тома `live-observations` и `runtime-observations`.

```bash
podman compose up --build
# или docker compose up --build
```

Интерфейс: <http://localhost:18080>. API: <http://localhost:18000/docs>. Порты настраиваются переменными `WEB_PORT` и `API_PORT`. На macOS, если Podman VM не пробрасывает порты, можно запустить `python3 scripts/podman_tunnel.py` в отдельном терминале.

Локальная разработка:

```bash
uv sync --project backend --extra demo --extra test
backend/.venv/bin/uvicorn app.main:app --app-dir backend --reload
cd frontend && npm ci && npm run dev
```

## Что реально считает сервис

| Шаг | Источник | Результат |
|---|---|---|
| Вода | VV/VH Sentinel‑1, 5 моделей U‑Net ResNet34, калибровка Platt | p, маска при p ≥ 0,41, разброс ансамбля |
| Сравнение | VH < −23,6 dB; ручная метка только для диагностики | IoU/F1/precision/recall основного метода и baseline на общей валидной области |
| Риск | p в пикселе точки, среднее 3×3 для проверки устойчивости; учебные V и q из кейса | EL = p × V × q для каждого из 10 объектов |
| Закупка | зоны от 1 км², бюджет, дедлайн, обязательный объект | точный выбор корзины C, сравнение с A и широкой B |
| Цена | формула постановления №840 с выбранной редакцией коэффициентов | сценарный тариф 788,64 ₽/км², скидка по общей площади корзины |

Для произвольной области каталог [Microsoft Planetary Computer Sentinel‑1 RTC](https://planetarycomputer.microsoft.com/docs/changelogs/history) отдаёт снимки и даты. Сервер загружает VV и VH Cloud Optimized GeoTIFF, объединяет соседние кадры только с одной платформы, абсолютной орбиты и `datatake`, переводит линейную интенсивность в dB, применяет обученную на Sen1Floods11 нормализацию и пять моделей без дообучения. Это перенос на другой продукт S1: численная точность на новом регионе без ручной разметки **не измерена**. Снимок исторический или актуальный на указанную дату, не прямой эфир.

Модель и baseline взяты из [ML-пакета этого проекта](ml/README.md). Веса ансамбля лежат в Git LFS. Метрики независимого `test_core` (55 чипов, 11,56 млн валидных пикселей): IoU **0,519 → 0,697**; для отдельного события Bolivia: **0,535 → 0,655**. Это оценка качества карты, а не оценка предотвращённого ущерба. Для новых регионов раздел «Качество» показывает эти метрики как внешнюю проверку модели, а локальные IoU/F1 оставляет пустыми, пока нет ручной метки.

Сумма EL — модельная экспозиция учебного портфеля. «Охваченный EL» означает риск объектов, для которых планируется дополнительное наблюдение; он **не равен физически предотвращённому ущербу**. Разница стоимости B и C — экономия бюджета на данных при заданном тарифе, а не доказанный экономический эффект в мире. Новая съёмка через 6 часов — сценарное допущение. Постоянная вода не отделяется от паводковой. Во вновь выбранном регионе координаты 10 объектов и V/q сценарные; они не являются реальным реестром инфраструктуры.

## Сцены и работа в интерфейсе

Три офлайн демонстрационные сцены [Sen1Floods11 v1.1](https://github.com/cloudtostreet/Sen1Floods11): Nigeria_812045 (21.09.2018), Ghana_313799 (18.09.2018), Mekong_333434 (05.08.2018). Каждый GeoTIFF прошёл замороженный inference без дообучения. Стартовый чип — Нигерия. Из любой точки карты можно перейти к новому региону:

1. Переключать схему и спутниковую подложку, регулировать видимость аналитического слоя, включать радар VH, маску, p, неопределённость, пороговый baseline и ручную метку. Спутниковая подложка нужна для ориентации: её дата может отличаться от Sentinel‑1, а расчёт модели сделан по радару. Ручная метка показана как контроль, а не источник рабочего прогноза.
2. Протягиванием рамки мышью или пальцем выбрать область от 1,25 км по каждой стороне до 300 км². Каталог предложит до шести проходов с VV/VH; соседние кадры одного прохода объединяются без смешения дат. Первый проход обработается автоматически. Выпадающий список позволяет сменить дату. Если остаются невалидные пиксели, процент фактического покрытия виден отдельно. На узком экране панель сворачивается на время выделения.
3. Выбрать объект на карте или в списке, посмотреть p, неопределённость, V/q и EL, закрепить его в плане.
4. Нажать на пиксель карты: увидеть p воды, разброс ансамбля и сравнение с baseline. Ручная метка доступна только на офлайн сценах Sen1Floods11. Кнопка «3D-обзор» наклоняет карту для ориентации на местности.
5. Изменить бюджет, срок и цель плана. Сервис пересчитает стоимость с объёмной скидкой, объяснит недостижимость обязательного объекта, сравнит A/B/C и экспортирует решение. Карточка объекта показывает чувствительность EL и ранга к p/V/q, план — к бюджету и ставке.
6. Переключить светлую и тёмную темы; выбор сохраняется в браузере.
7. В панели «Другой снимок» найти официальный чип Sen1Floods11 и запустить расчёт. Этапы скачивания, inference и сборки видны в интерфейсе; готовая сцена становится вкладкой карты. Для чипов из train/valid или соседних с train качество не считается независимой проверкой.

ZIP содержит `flood_probability.tif`, `flood_mask.tif`, `flood_uncertainty.tif`, `baseline_mask.tif`, `assets.csv`, `asset_loss.csv` (все 10 объектов, признак `in_region`), `candidate_orders.geojson`, `procurement_plan.csv`, `strategy_comparison.csv`, `sensitivity.csv`, `metrics.csv`, манифесты и входные параметры. Все слои относятся к одному выбранному чипу; таблица качества независимой выборки прилагается отдельно.

Проверка выгруженного комплекта одной командой (нужен `uv sync --project backend --extra demo`):

```bash
curl -o floodvalue-Nigeria_812045.zip 'http://localhost:18080/api/export?scene_id=Nigeria_812045&budget=6500'
backend/.venv/bin/python scripts/validate_package.py floodvalue-Nigeria_812045.zip
```

Валидатор проверяет обязательные файлы, 10 уникальных типов объектов, pVq, сценарии чувствительности, Polygon без вырезов и площадью от 1 км², стоимость B/C, бюджет, валидные вероятности и равенство маски правилу p ≥ 0,41. Прокси-проверка на ручной метке тестового чипа оценивает ошибку переноса p в EL; она не измеряет фактический денежный ущерб.

## Воспроизведение данных

Компактные выходы модели лежат в `data/demo`. Исходные GeoTIFF и промежуточный inference намеренно не включены в Git. Для полного пересоздания скачайте три пары `S1Hand`/`LabelHand` из официального бакета `sen1floods11/v1.1` в `data/source`, затем:

```bash
git lfs install --local
git lfs pull
uv sync --project ml
uv sync --project backend --extra demo
for chip in Nigeria_812045 Ghana_313799 Mekong_333434; do
  ml/.venv/bin/floodvalue infer --s1 "data/source/${chip}_S1Hand.tif" --out "data/inference/${chip}"
done
backend/.venv/bin/python scripts/prepare_demo.py
```

`scripts/prepare_demo.py` сверяет размер, CRS и сетку растра, фиксирует SHA‑256 источника и выходов, строит слои для карты и независимый от ручной метки учебный портфель. Идентификаторы и характеристики десяти объектов фиксированы для каждого чипа; p берётся из модели. Метрики по `test_core` и Bolivia копируются из [отчёта ML](ml/REPORT.md).

## Проверки и структура

```bash
backend/.venv/bin/pytest backend/tests -q
cd frontend && npm run build && cd ..
# После podman compose up -d или docker compose up -d:
python3 scripts/e2e_live.py http://127.0.0.1:18000 5.8,9.07,5.83,9.1
python3 scripts/e2e_live.py http://127.0.0.1:18000 5.8,9.07,5.83,9.1 1  # два соседних кадра одного прохода
python3 scripts/e2e_official.py http://127.0.0.1:18000 Ghana_1078550
```

Последняя команда проходит внешний STAC, VV/VH COG, inference, анализ, пиксель, смену бюджета и ZIP. Браузерный путь проверяется отдельно на `http://localhost:18080`: рамка → дата → объект → план → экспорт.

- `backend/app` — FastAPI, анализ региона, риск, планирование, экспорт.
- `frontend/src` — Vue и 3D MapLibre; рабочий интерфейс вдохновлён пространственной компоновкой [krasnoyarsk_kosmos](https://github.com/Mojarung/krasnoyarsk_kosmos), а инспектор пикселя и наклонный обзор — приёмами карты [final_kosmostarsa](https://github.com/Mojarung/final_kosmostarsa), с другой палитрой и сценариями кейса.
- `ml` — исходный пакет модели, веса, протокол split и независимая оценка.
- `data/demo` — подготовленные реальные выходы модели для трёх сцен; `data/catalog` — официальный список чипов; тома `live-observations` и `runtime-observations` — новые RTC области и рассчитанные официальные чипы.
- `scripts` — сборка демо-данных и локальный туннель Podman.
- `docs/source` — постановка и критерии; `docs` — подробный разбор и [продуктовый сценарий](docs/product.md).

Kafka, Redis и внешняя LLM для демонстрационной нагрузки не нужны: новый снимок кэшируется по STAC ID и рамке, а план пересчитывается локально без повторного inference. Присланный ключ никуда не записывался и не используется.
