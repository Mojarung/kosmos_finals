# Данные: Sen1Floods11 и дополнительные источники

Источники: постановка, с. 3, 8-10; README и `docs/README.md` репозитория [cloudtostreet/Sen1Floods11](https://github.com/cloudtostreet/Sen1Floods11); проверка бакета 25.09.2026.

## Доступ

Данные лежат в публичном бакете Google Cloud Storage `sen1floods11`, актуальная версия в папке `v1.1`. В README авторов бакет в одном месте записан с опечаткой (`gs://senfloods11/`), рабочее имя `sen1floods11`.

```bash
# весь набор, около 14 ГБ
gsutil -m rsync -r gs://sen1floods11 ./data/sen1floods11

# только то, что нужно для ручной разметки
gsutil -m rsync -r gs://sen1floods11/v1.1/data/flood_events/HandLabeled/S1Hand    ./data/S1Hand
gsutil -m rsync -r gs://sen1floods11/v1.1/data/flood_events/HandLabeled/LabelHand ./data/LabelHand
gsutil -m rsync -r gs://sen1floods11/v1.1/splits ./data/splits
```

Без gsutil файлы отдаются по HTTPS (проверено):
`https://storage.googleapis.com/sen1floods11/v1.1/data/flood_events/HandLabeled/S1Hand/Ghana_313799_S1Hand.tif`.

Один S1Hand-чип весит около 1,8 МБ, метка около 6 КБ, так что 446 размеченных чипов S1 с метками занимают меньше 1 ГБ. В GitVerse набор не кладем, в README описываем, как его получить.

## Проверено на чипе Ghana_313799

| Свойство | S1Hand | LabelHand |
|---|---|---|
| Каналы и тип | 2 × float32 | 1 × int16 |
| CRS | EPSG:4326 | EPSG:4326 |
| Объявленный nodata | NaN | не задан |
| Размер пикселя | 8,98315e-05° (около 10 м) | тот же, сетки совпадают |
| Диапазон | VV от -26,1 до -0,3 dB; VH от -37,9 до -6,6 dB | -1, 0, 1 |
| NaN в этом чипе | 0 | - |
| Геодезическая площадь bbox | 25,70 км² | 25,70 км² |

Отсюда три практических вывода. Невалидные пиксели S1 кодируются через NaN, поэтому маску валидности строим как `~isnan(VV) & ~isnan(VH)` и объединяем с `label != -1`. У метки nodata в метаданных не задан, -1 надо обрабатывать явно. Номинальные 26,2144 км² из постановки верны только у экватора: на 9° с. ш. площадь чипа уже 25,70 км², а на широте Испании или США (около 40°) выйдет примерно 20 км². Это прямо влияет на цену зоны, если она покрывает весь чип.

## Авторский split: главная ловушка

Все 10 событий, кроме Bolivia, одновременно присутствуют в train, valid и test. Авторы делили случайно по чипам внутри событий, поэтому test не независим по событиям, и соседние чипы одной сцены могут оказаться по разные стороны границы. Критерий 6 прямо требует исключить или явно учесть пересечения событий и соседних окон.

Варианты, которые проходят критерий:

- взять авторский split, но по bbox из `CNN_Chips_FTC.geojson` найти test-чипы, соседние с train, и убрать их или вынести в отдельный срез; Bolivia оставить как независимое событие для проверки переноса;
- построить свой split по событиям (leave-event-out): целые события уходят в validation и test.

Рекомендую первый вариант как основной, а Bolivia держать нетронутой до финала: метрики сравнимы с литературой, и есть честная проверка на новом событии для критерия 7. Подробнее в [03-methods-validation.md](03-methods-validation.md#разделение-данных-без-утечки).

## Постоянная и временная вода

Метка 1 означает воду вообще. Чтобы заявить именно временное затопление, постоянные водоемы нужно исключить источником, который был доступен до даты события. Ближайший кандидат лежит в самом бакете: `JRCWaterHand`. Версию и период наблюдений JRC нужно выяснить и записать в `source_manifest.json`: если слой построен по данным, захватывающим дату события, это утечка будущего. Если отделение не сделано или не обосновано, результат называем «карта воды».

## Ловушки при подготовке

- S1 уже в dB. Повторное логарифмирование ломает признаки.
- Статистики нормализации считаем только по train своей выборки.
- Радар видит обратное рассеяние, а не воду. Гладкая вода темная, но тени, рельеф, асфальт и песок дают похожий сигнал; в застройке и растительности ошибки выше. Спекл надо анализировать отдельно.
- EPSG:4326 в градусах. Площадь по широте и долготе напрямую не считается: переводим в EPSG:6933 или считаем геодезически.
- Порядок осей: в EPSG:4326 формально «широта, долгота», в GeoJSON (RFC 7946, OGC CRS84) «долгота, широта». В pyproj задаем `always_xy=True`.
- S2: при приведении SWIR (20 м) к сетке 10 м пиксель мельче, но разрешение исходного канала не растет. Маски ресэмплируем nearest-neighbor, непрерывные поля по смыслу.
- NDWI понимают по-разному. Для открытой воды обычно `(Green - NIR) / (Green + NIR)`, MNDWI использует SWIR вместо NIR. Нулевой знаменатель, nodata и облака обрабатываем отдельно.
- Встроенной QA-маски облаков у S2Hand нет. Если команда добавляет S2, оценку качества, дату и совмещение с S1 делает сама, а S1-only запуск должен работать без оптики.

## Манифест источников

`source_manifest.json` описывает каждый использованный источник, включая обязательный S1:

| Поле | Пример |
|---|---|
| идентификатор или файл | `Ghana_313799_S1Hand.tif` |
| URL | `https://storage.googleapis.com/sen1floods11/v1.1/...` |
| версия | `v1.1`, либо контрольная сумма файла |
| дата наблюдения | `2018-09-18` |
| дата публикации или доступности | когда источник стал доступен |
| лицензия | по README авторов и каждого доп. источника |
| назначение | train, valid, test, demo, признак, постоянная вода |
| ограничения | что источник не гарантирует |

Метки и дополнительные данные привязываются к тем чипам, к которым применимы. Chip_id, event_id, разбиение и контрольные суммы дублируются в `run_metadata.json`.
