# План пилота FloodValue

Пилот проверяет одно решение: дежурный аналитик инфраструктурного оператора после паводка за 6–12 часов выбирает, какие объекты проверять первыми и какие снимки докупить. Остальные роли из постановки (страховой аналитик, оператор ДЗЗ) в пилот не входят.

Метрики берутся из постановки для инфраструктурного оператора ([01](01-case-overview.md#кто-пользователь)): время от данных до решения, пропуски значимых объектов, доля ручной проверки. Цифры порогов ниже предлагаются командой и согласуются с оператором до старта. Сейчас это не результат, а условия проверки.

## Что нужно от оператора

| Что | Зачем | Минимум |
|---|---|---|
| Реестр объектов: координаты, тип, стоимость V, уязвимость q, лицензия на использование | Заменить 10 учебных точек реальным портфелем | 200 объектов в одном бассейне |
| Два-три прошлых паводка в том же регионе с датами | Ретроспективная проверка без ожидания нового события | Даты, по которым есть Sentinel‑1 |
| Результаты обходов по этим паводкам: какой объект был в воде | Проверка «в воде / сухо» в точках объектов | 50 объектов с отметкой и датой |
| Котировка поставщика оптики 1 м на новую съёмку | Заменить сценарную ставку 788,64 ₽/км² | Одна котировка с условиями и сроком |

## Этапы

1. **Ретроспектива, 2 недели.** Для каждого прошлого паводка сервис строит карту воды по Sentinel‑1 RTC, отделяет постоянную воду по снимкам за год до события и ранжирует объекты реестра. На 5–10 участках по 5×5 км вода размечается вручную по оптике того же дня. Считаем IoU/F1 модели и порога VH на этой разметке, калибровку p и совпадение статуса объектов с обходами.
2. **Параллельный режим, один сезон.** Дежурная смена работает как обычно, сервис считает план рядом. Фиксируем, когда появились данные, когда было решение по старой схеме и когда его выдал сервис; какие объекты смена проверила сама и какие были в верхних строках рейтинга.
3. **Полевая проверка.** После первого паводка сезона выездная группа проверяет 30 объектов: 20 из верхней части рейтинга и 10 случайных. Статус «в воде / сухо» сравнивается с картой.
4. **Закупка по плану C.** Один заказ оптики по зонам плана C с реальной котировкой. После поставки проверяем, изменил ли новый снимок статус объектов в сомнительных участках.

## Метрики пилота

| Метрика | Как считаем | Предлагаемый порог успеха |
|---|---|---|
| Качество карты в регионе | IoU модели и порога VH на ручной разметке этапа 1 | модель не хуже порога VH; IoU не ниже 0,5 |
| Надёжность вероятностей | ECE p на той же разметке | не выше 0,05 |
| Время от данных до решения | от публикации снимка Sentinel‑1 до готового плана | не больше 1 часа |
| Пропуски значимых объектов | доля объектов, затопленных по обходу, которых нет в верхних 20% рейтинга | не больше 10% |
| Доля ручной проверки | объекты, которые смена проверила сама, от числа затопленных | меньше, чем по старой схеме того же сезона |
| Цена покрытия сомнений | стоимость C и B при одной доле сомнительной площади по котировке | C дешевле B не меньше чем на 30% |

## Когда остановить пилот

- Модель на разметке региона хуже порога VH или IoU ниже 0,3: без дообучения на регионе сервис не даёт преимущества.
- ECE выше 0,1: вероятностям нельзя верить, а на них держатся EL и сомнительные участки.
- В полевой проверке статус «в воде / сухо» расходится с картой больше чем у трети объектов.
- Котировка поставщика делает C не дешевле B при той же доле сомнительной площади.

## Что пилот не покажет

Предотвращённый ущерб пилот не измеряет: для этого нужна модель действий смены и последствий пропуска. Годовой ожидаемый ущерб и страховые резервы тоже за пределами пилота.
