## Очередность этой итерации

1. Исправить внутренние противоречия ZIP, внедрить данные о времени источников в API и UI, гарантировать commit сборки для Podman/Docker.
2. Связать реальные активы проекта с решением/подбором; не подменять ими обязательные десять учебных объектов.
3. Проверить unit, экспорт и браузерный путь на финальной сборке; записать **новую** диагностическую таблицу по всем 20 пунктам с источником доказательства.
4. Отдельно отметить то, что нельзя объявить выполненным кодом: анонимный доступ GitVerse, новые независимые метки RTC/событий, фактический ущерб, права на коммерческую котировку.

Нельзя присвоить 10 только за наличие поля или красивого экрана. Для каждого пункта нужно продемонстрировать результат на данных и честно указать границы применимости.
