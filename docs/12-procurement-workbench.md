# Реальные спутниковые снимки: каталог, покрытие и сравнение

Переработано 26.09.2026. Экран: **Съёмка → Каталог SkyFi**.

## Зачем это бизнесу

Оператор видит доступные архивные кадры для выбранной территории, их настоящие
превью, даты, детализацию, облачность и предварительные цены. Может сравнить
до четырёх кадров и скачать обоснование выбора. Это помогает понять, какие
данные доступны, сколько они стоят и какую часть территории покрывают.

Учебный генератор предложений удалён. Без ключа или при ошибке API приложение
показывает причину; подставных цен, изображений и фонового переключения на
фиктивный каталог нет. Сохранённый ответ реального API имеет дату получения.
Старые учебные каталоги не открываются.

## Интерфейс

- **Галерея:** изображения поставщиков, дата, цена, разрешение и доля покрытия.
- **Карточка снимка:** большое превью, реальный контур пересечения с территорией,
  площадь, условия заказа, источник и идентификатор SkyFi. Превью можно увеличить.
- **Графики:** цена относительно покрытия; распределение кадров по годам.
  Точка открывает карточку, столбец года фильтрует галерею.
- **Условия:** лимит расходов на данные в USD, детализация и облачность.
  Автоподбор сравнивает одиночные кадры и пары: сначала ищет самый дешёвый
  вариант с покрытием не менее 95%, затем максимальное покрытие в лимите.
  Цены берутся из каталога. Утверждения об оптимальности среди наборов из трёх
  и более кадров нет.
- **Сравнение:** до четырёх выбранных изображений рядом, сумма цен, географическое
  объединение покрытия, непокрытая площадь и повторное покрытие.
- **На карте:** контуры выбранных кадров поверх основной карты.
- **Экспорт:** ZIP с `comparison.html`, `decision.json`, `coverage.geojson`.
  HTML можно распечатать; для загрузки превью в нём нужен интернет.

Вариант с нулём снимков не отображается как бесплатная покупка. Если фильтры
слишком строгие, каталог остаётся видимым; если за период нет данных, интерфейс
предлагает расширить период. Статус пригодности для анализа не подменяется
доступностью превью.

## Откуда данные

Ключ `SKYFI_API_KEY` задаётся только в окружении backend (локально — игнорируемый
`.env`). Браузер не получает ключ. Сервер вызывает:

- `POST /archives` и `GET /archives?page=...`: до трёх страниц по 100 записей.
- `POST /order-archive/validate`: проверка оценки стоимости, без создания заказа.

Документация: [OpenAPI SkyFi](https://app.skyfi.com/platform-api/openapi.json).
Из ответа сохраняются исходный идентификатор, дата, GSD, footprint, URL превью,
цены, облачность, ограничения площади и дата получения каталога. GSD переводится
из сантиметров в метры. Предварительная цена — тариф за км² × площадь пересечения,
либо цена целого кадра, если его нельзя обрезать. Контур, нарушающий ограничения
поставщика, не включается в автоподбор. Финальная проверка цены выделена отдельно.
Облачность относится ко всему кадру, а не к конкретной точке внутри территории.

**Временной контекст:** кадр другой даты не подтверждает паводок исходной сцены.
В карточке видна разница дат; кнопка «Неделя паводка» запрашивает реальный архив
за соответствующий период. Современные кадры полезны для изучения территории
и проверки доступности данных; они не объявляются наблюдением события 2018 года.
Расчёт A/B/C по ТЗ остаётся в соседнем режиме «Расчёт по ТЗ».

## Сценарий показа жюри

1. Нигерия → Съёмка → Каталог SkyFi. Показать реальные фотографии и источник.
2. Открыть кадр: дата, разрешение, цена, контур покрытия. Увеличить изображение.
3. Добавить два кадра к сравнению: покрытие географически объединяется, а цены
   суммируются. Два кадра всей территории не дают 200% покрытия.
4. Открыть графики, выбрать точку или год. Изменить лимит и показать изменение
   предложенного варианта. При нулевом лимите нет фиктивной бесплатной корзины.
5. Показать контуры на карте и скачать визуальное сравнение.
6. Переключиться на Меконг: при лимите 500 USD доступный вариант покрывает только
   часть территории, что сразу видно на контуре и в процентах.

## Проверки

```sh
cd backend
.venv/bin/python -m pytest tests/test_procurement.py -q
```

```sh
cd frontend
npm run build
npx playwright test tests/e2e/procurement.spec.js
```

Серверные тесты используют зафиксированные реальные ответы SkyFi для проверки
математики. Эти файлы находятся только в `backend/tests/fixtures` и не служат
источником данных приложения. Браузерные проверки обращаются к реальному SkyFi
через backend, без подмены API и картинок. Для них нужен рабочий ключ в `.env`.
Playwright запускает отдельные API/Vite на 18031/5178 и отдельную SQLite в `/tmp`;
сохраняет скриншоты и скачанное сравнение в `frontend/test-results`.

Проверка этой переработки: 22 серверных теста закупки прошли; 7 браузерных
сценариев прошли с настоящими ответами SkyFi (три территории, мобильный экран,
сравнение и экспорт, пустой период, отказ проверки цены). Production-сборка
фронтенда прошла; сохраняется предупреждение о размере основного JS-бандла.
