# Реальные здания и сценарный ущерб

## Как показать жюри

1. Открыть **Объекты → Здания** (режим по умолчанию). Контуры загружаются автоматически
   после готовности каждого снимка. Для подготовленного примера открыть **Данные и настройки → Пример: Пайпорта**. Контуры и результат модели
   сохранены в репозитории: API OSM и запуск нейросети во время показа не нужны.
   Спутниковая подложка по-прежнему загружается из сети.
2. В списке сразу виден **топ‑10 по среднему сигналу воды** (при равенстве — по сценарию ущерба).
   Здания без цены участвуют в рейтинге, без данных радара — нет. Все контуры доступны на карте.
   Выбрать здание на карте или в списке; объект вне десятки откроется как дополнительный. В карточке есть тип, основание классификации,
   ссылка на OSM, площадь контура, покрытие радаром и полный расчёт в рублях.
3. В **Поиск → Условная цена** выбрать объект и уточнить назначение в **Тип и стоимость**.
   Ручные уточнения относятся к текущему расчёту и сохраняются в выгрузке.
4. В карточке сразу видны стоимость первого этажа и сценарный ущерб. В **Как получилась сумма** расчёт разделён на три шага: условная стоимость первого этажа,
   потери при заданном проценте повреждения и сценарный ущерб с учётом сигнала воды.
   Рядом показано происхождение ставки и процента. Открыть **Тип и стоимость**,
   изменить значения и нажать **Применить к этому типу**: пересчитаются все здания этого типа.
   Для нескольких типов есть общая таблица **Стоимость и повреждение по типам** и кнопка
   **Применить ставки**. Незавершённые изменения других типов сохраняются при применении одного.
   Ставки сохраняются в браузере и применяются при новой загрузке.
5. Нажать **Скачать расчёт**: ZIP содержит GeoJSON, CSV, ставки и паспорт расчёта.

В другой сцене автоматическая загрузка получает OSM по границам снимка (до 300 км², как в режиме точек).
Область делится на части до 4 км². При отказе map API из-за плотной застройки часть
автоматически делится ещё раз (до трёх уровней); при недоступности источника есть
резервные серверы Overpass. Одновременно идут не более двух запросов, общий бюджет
загрузки — 900 с, фоновая задача сообщает процент готовности. Лимит XML-ответа OSM — 48 МБ, объединённого набора — 200 000 зданий
и 8 млн вершин. Полные геометрии не обрезаются на границе частей, здания объединяются
по OSM ID, части успешно собранных relations не учитываются повторно.
Сохраняются датированные снимки каждой завершённой части и всей области. Повторный
запрос использует кэш; если не все части получены, неполный набор не выдаётся за полный.
Неполные ответы Overpass с `remark` не считаются успешной пустой выборкой. Для других источников — импорт FeatureCollection с Polygon /
MultiPolygon в WGS84, до 5 000 объектов / 12 МБ. Теги назначения берутся из
`properties.tags` или непосредственно `properties`. Например:

```json
{"type":"FeatureCollection","features":[{"type":"Feature","id":"house-1",
"properties":{"name":"Дом","building":"house","building:levels":"2"},
"geometry":{"type":"Polygon","coordinates":[[[-0.417,39.427],[-0.4168,39.427],
[-0.4168,39.4272],[-0.417,39.4272],[-0.417,39.427]]]}}]}
```

## Метод

`Ущерб = площадь контура × ставка типа (₽/м²) × доля повреждения × среднее p воды`.

- Площадь — геодезическая площадь контура с учётом отверстий на WGS84.
- Среднее p взвешено по площади пересечения контура с каждой ячейкой растра
  в его координатной сетке. Это прокси среднего сигнала воды, **не калиброванная
  вероятность затопления отдельного здания**. Пересечение с бинарной маской воды
  отображается отдельно. Ненулевое p возможно при нулевом пересечении маски.
- При наличии маски постоянной воды её ячейки имеют эффективное p = 0.
  Если такой маски нет, интерфейс явно сообщает, что используется вся вода.
- Ставка относится к площади первого этажа. Этажность показывается справочно,
  ущерб не умножается на количество этажей. Не учитываются имущество и простой.
- 20 известных категорий и неуточнённый тип имеют независимые редактируемые ставки. Значения по умолчанию —
  **сценарные допущения команды**, не рыночные цены или официальные нормативы.
  Начальная доля повреждения 30% также является допущением и не выведена из глубины.
  В карточке и CSV/GeoJSON поля `cost_source` / `damage_source` отмечают, какие значения
  отличаются от исходных допущений команды. Переданные пользовательские настройки
  сохраняются в `rate_overrides` паспорта расчёта; `rates` содержит применённые значения.
  В сводке указаны число зданий в сумме и число условных цен.
- Для неизвестного типа назначается демонстрационная цена: 45 000 ₽/м² × коэффициент
  от 0,85 до 1,15 с шагом 0,01, детерминированный по SHA256 ID здания. Цена стабильна
  при перезагрузке. Тип при этом не выдумывается. `synthetic_cost`, `base_cost_rub_m2`
  и `cost_factor` сохраняются в GeoJSON/CSV. Базовую ставку можно изменить.
  Это пожелание пользователя для демонстрации, не рыночные данные.
- Тип: ручное уточнение → `building:use` → `amenity/shop/tourism/leisure` → `building`.
  `building=yes`, общие `residential/commercial` и нераспознанные значения остаются
  неизвестными. Если тегов контура недостаточно, учитываем назначение точек OSM строго
  внутри контура. Единственная категория даёт тип с указанием ID точки; конфликтующие
  категории оставляют тип неизвестным. Не выводим назначение из внешнего вида или соседних объектов.
- При пропусках радара, неполном покрытии контура или существенном наложении разных
  контуров ущерб по снимку не вычисляется. Карточка и список показывают **потери при
  затоплении** (стоимость × доля повреждения) с отдельной подписью. Эти суммы не
  подмешиваются в ущерб по снимку. Если по снимку нет ни одной оценки, сводка показывает
  условные потери при затоплении без пересекающихся контуров с соответствующим заголовком. Одинаковые геометрии удаляются как дубли; повторные ID отклоняются.
- OSM multipolygon собирается с внутренними кольцами; успешно собранные отношения
  исключают повторное включение своих member ways. Неполные отношения пропускаются.

## Проверенный пример и ограничения

**Пайпорта, Испания.** Контуры получены 26.09.2026 из
[официального OSM API](https://api.openstreetmap.org/api/0.6/map?bbox=-0.420,39.424,-0.410,39.431),
лицензия [ODbL](https://www.openstreetmap.org/copyright), © OpenStreetMap contributors.
Сохранены 908 замкнутых building ways; это фрагмент, а не полный реестр города.
Типы распознаются у 239 (в том числе 2 благодаря точкам OSM внутри контуров),
остаются неизвестными у 669.

Реальный радар:
`S1A_IW_GRDH_1SDV_20241101T060207_20241101T060232_056357_06E766_rtc`,
01.11.2024 06:02:19 UTC, Planetary Computer `sentinel-1-rtc`.
Область обработки `[-0.427,39.419,-0.403,39.439]`, приблизительно 10 м/пиксель.
Снимок обработан существующим замороженным `next_optical`, режим **S1 fallback**,
без оптики и маски постоянной воды. Использована штатная RTC harmonization.
В `data/demo/Paiporta_20241101/metadata.json` записаны ID, даты, URL VV/VH,
лицензия, SHA256 окна входных данных, SHA256 рецепта модели и время обработки.
Сырые подписанные URL и секреты не сохраняются.

На этом снимке **ни один из 908 контуров не пересекает бинарную маску воды**.
В версии ставок v1 сумма `7 903 003,12 ₽` относилась только к 239 классифицированным зданиям.
В v2 добавлены условные цены 669 зданий с неизвестным типом; это меняет общую сумму.
Ненулевой ущерб по снимку получается из вероятностей ниже порога маски. Это **не подтверждённый
ущерб паводка 2024 года**, не валидация его денежного размера и не доказательство,
что здания не затапливались. Снимок позже пика события, городской SAR сложен,
контуры 2026 года не проверены на существование в 2024 году.

Для валидации фактического ущерба нужны независимые данные по глубине/осмотрам и
локальные восстановительные ставки. Следующий исследовательский шаг — сопоставить
здания с независимой картой паводка и полевыми наблюдениями, затем калибровать q.

Основания для трактовки источников:

- [OSM building:use](https://wiki.openstreetmap.org/wiki/Key:building:use) — назначение и тип постройки могут различаться.
- [JRC, Global flood depth-damage functions, 2017](https://publications.jrc.ec.europa.eu/repository/handle/JRC105688) — функция ущерба зависит от глубины и класса; её старые цены не выдаются здесь за текущие рублёвые ставки.
- [CEMS, flood modelling and depth mapping](https://mapping.emergency.copernicus.eu/about/rapid-mapping-manual/detection-methods-damage-assessment/enhanced-flood-modelling-and-depth-mapping-capabilities-exflos/) — ограничения обнаружения воды в городской застройке и роль дополнительных данных.

## Объёмные здания и точки

Здания показаны через `fill-extrusion`. Высота: `height` из OSM; при отсутствии —
`building:levels × 3 м`; иначе **условные 6 м**. Карточка показывает происхождение
и признак приблизительной высоты. Высота влияет только на отрисовку, формула ущерба
не меняется. Подсветка выбранного объёма и обводка десятки помогают найти объекты.

В «Объектах» есть переключатель **Здания / Точки**. Учебные точки, их карточки,
формула кейса, экспорт, проекты и планирование съёмки сохранены. При выборе точки
из планирования открывается её режим; здания не заменяют данные портфеля на сервере.

## API и хранение

- `GET /api/buildings/rates` — категории, ставки и методика.
- `GET /api/buildings/demo` — ID подготовленной сцены.
- `POST /api/buildings/load` — `{scene_id, source: "auto" | "osm" | "paiporta", rate_overrides?}`; `auto` по умолчанию
  использует сохранённый набор Пайпорты в соответствующей сцене, иначе OSM.
- `POST /api/buildings/load?background=true` — запускает фоновую загрузку;
  `GET /api/buildings/load-jobs/{job_id}` возвращает queued/loading/ready/error,
  progress и catalog_id; затем `/evaluate` считает ущерб с текущими ставками.
- `POST /api/buildings/import` — `{scene_id, content: "GeoJSON", rate_overrides?}`.
- `POST /api/buildings/evaluate` — `{scene_id, catalog_id, rate_overrides?, type_overrides?}`.
- `POST /api/buildings/export` — тот же запрос, ZIP с серверным пересчётом.

`rate_overrides[type] = {cost_rub_m2, damage_ratio}`, `type_overrides[id] = type`.
В ZIP входят применённые уточнения, ставки, дата радара, источник контуров,
хэши источника и растров, формула, сумма и число исключённых зданий.
CSV нейтрализует формулы в пользовательских названиях.

Источники хранятся в `FLOODVALUE_BUILDINGS_DIR` (по умолчанию
`data/buildings-cache`, в Compose отдельный volume). Набор неизменяемый,
ID определяется содержимым. При смене сцены фронтенд отменяет старый запрос и
очищает контуры; поздний ответ не восстанавливает данные прежней сцены.

## Планирование съёмки по зданиям

В «Съёмке» теперь есть переключатель **Здания / Точки**. Для зданий доступны
все загруженные контуры или подборка: **Выбрать здания на карте → клики по домам → Готово**.
Выбранные контуры жёлтые; повторный клик снимает выбор. При выборе карта не
перемещается и расчёт не запускается до «Готово». Счётчик «Выбранные · 0» означает
пустую ручную подборку; режим «Все здания» уже использует все загруженные дома.
В карточке также остаётся кнопка **В план съёмки**.
Точки и проектный сценарий остаются отдельными.

- **По бюджету**: максимум суммы ожидаемого ущерба у полностью охваченных зданий
  при заданном бюджете и сроке. Это приоритет проверки, не предотвращённый ущерб.
- **По пользе**: максимум сценарной экономии на решениях за вычетом цены снимков.
  Для каждого здания `до = min(выезд, p × V × q)`,
  `после идеального снимка = p × min(выезд, V × q)`.
  Разность — ценность информации; `p` остаётся сигналом модели, не проверенной
  вероятностью затопления дома. Обработка вынесена отдельно от цены снимков.
- **SkyFi**: каталог подбирается для границ выбранных зданий, охват и рекомендации
  считаются по полным полигонам и их ущербу. Реальные цены требуют API-ключ.
  Заказы не отправляются.

Используются те же ставки, ручные типы, условные цены и повреждаемость, что
в карточках зданий. Пропуски радарных данных не получают выдуманный ущерб:
стоимость дома есть, вес ущерба/пользы для подбора равен нулю.

Сценарный план создаёт до десяти пространственных групп и общую зону, перебирает
все их сочетания. Это точный поиск среди этих кандидатов, не глобальный оптимум
геометрии. Прямоугольники содержат полные контуры, площадь каждой зоны ≥1 км².
Дом считается один раз, даже если попал в несколько зон; частичное пересечение
не засчитывается. Цены зон включают прежний групповой тариф.

Синим на 3D-карте выделяются здания в охвате. Покрытие отмечено заливкой,
контрастной голубой рамкой и подписью «Зона N · K зданий». Кнопка **Показать
покрытие на карте** помещает все выбранные зоны в экран и сворачивает мобильную панель.
ZIP включает план, зоны GeoJSON и отдельную папку с выбранными зданиями, CSV,
ставками, источниками и хэшами.

API: `POST /api/building-plans`, `/export`, `/imagery/plan`, `/imagery/export`.
Поле `buildings` содержит параметры `/api/buildings/evaluate` и
`target_ids` (`null` — все, непустой список — подборка). Сценарный запрос также
содержит `budget_rub`, `deadline_hours`, `method`, `visit_cost_rub`, `strategy`.

Проверка запущенного сервиса 26.09.2026: для 4 007 московских зданий при 6 500 ₽
и 8 ч выбраны три зоны за 6 166,89 ₽, 1 680 зданий и 69 324 333,80 ₽ ущерба
в охвате. Успешно сформирован ZIP. Это сценарный расчёт на реальных контурах.
Сборка фронтенда выполнена; автоматические тесты и CI для этой доработки
не запускались.

## Повторный сбой OSM: причина и исправление

На области `live_7d2f260840204530` в Италии (156,108 км²) загрузка останавливалась
на 98%. В журнале была локальная ошибка `площадь должна быть от 1 до 2 000 000 м²`
для контура `way/1511991550`. Одинаковые данные повторно запрашивались с разных
серверов, затем область дробилась; ошибка ошибочно показывалась как недоступность OSM.

Теперь некорректный, неполный или слишком маленький отдельный контур из OSM
исключается с ID и причиной в `source.excluded_features`. Причины и количество
видны в интерфейсе и ZIP. Остальные контуры обрабатываются. Ручной GeoJSON
по-прежнему проходит строгую проверку. Локальные ошибки данных не маскируются
как сетевой отказ. Сетевой отказ больше не вызывает рекурсивного дробления;
фоновая задача автоматически повторяет недостающие части до трёх попыток в рамках
общего бюджета 900 с. Сетевые ограничения источника остаются реальными.

Проверка на исправленном запущенном API: загрузка → оценка → план при 6 500 ₽ / 8 ч.

Точки строятся из учебного портфеля, реальные контуры зданий требуют источника OSM
или GeoJSON. Пустой OSM не означает отсутствие зданий на местности. Изменение p
в анализе чувствительности — отдельный сценарий, исходный растр не изменяется.
Статистика по контуру не подменяется значением в центре здания.

API планирования принимает `priority`, `must_cover`, `base_rate_rub_km2`,
`processing_level`, `usage_type`. Сохранение: `POST /api/building-plans/projects/{project_id}`;
выгрузка сохранённого результата: `GET /api/building-plans/projects/{project_id}/{plan_id}/export`.
Проверяется принадлежность проекту и снимку; архив фиксируется при сохранении,
позднее изменение ставок не пересчитывает историю.

Проверки после исправления: **187 серверных тестов прошли**, сборка фронтенда прошла.
Регрессия покрывает маленький контур в нормальном ответе OSM без повторного обращения
к провайдерам, отсутствие рекурсивных запросов при сетевом отказе, обязательный
охват/недостаточный бюджет, чувствительность и сохранённый неизменяемый архив.

В браузере дополнительно проверены изменение приоритета, нехватка бюджета для обязательного дома,
чувствительность в карточке и сохранение плана 53 зданий Нигерии в проект с доступной выгрузкой.

После общего прогона добавлены проверки автоматического повтора с общим дедлайном и независимости тарифов: 36 целевых тестов прошли.
