# Две возможности для оператора: ретроспектива и цена информации

Состояние на 26.09.2026: обязательный путь S1 → p → десять учебных объектов → зоны → A/B/C работает; C выбирается точным перебором при заданном бюджете. Цена 788,64 ₽/км² и сроки поставки сценарные. Эффект новой съёмки пока показан только через охват и сценарный остаток сомнений. Коммерческий SkyFi каталог — отдельный путь с USD; к этому сравнению он не относится. Оценка `143/200` в `docs/16-strict-audit-2026-09-26.md` — самоаудит, не оценка жюри.

## 1. Ретроспективная проверка закупки

**Пользователь и действие.** Дежурный оператор видит, помогла бы выбранная корзина C исправить оценку риска у объектов на уже размеченных паводках, и может объяснить руководителю результат вместе с разбросом и ценой B.

**Требования и контракт.**

1. Ровно 55 `test_core` и 15 Bolivia из сохранённого split; фиксированные S1-прогнозы `service_s1`, десять позиций и V×q по правилу аудита 13. Прогнозы, объекты, зоны, A/B/C, бюджет 6 500 ₽, срок 8 ч и цель «ущерб» фиксируются до чтения ручной метки.
2. Использовать production-генератор зон, цену, правило выбора продукта и точный перебор C. A не покупает; B покупает всю область как контрфактическое сравнение и может превысить бюджет; C соблюдает лимит. Архивный кадр не раскрывает метку.
3. Для оценимых объектов внутри своевременно купленной зоны подменить p на y∈{0,1}; вне зоны сохранить p. Объекты с невалидной меткой исключить одинаково для A/B/C. Отдельно посчитать исходную и новую сумму `|pVq−yVq|`, число исправленных статусов воды/суши, стоимость C/B, результаты по двум группам и описательный 95% bootstrap по чипам.
4. В интерфейсе «Съёмка» дать измеренную сводку, разброс, числа объектов и явное объяснение методики. Для новых ROI без ручной метки показывать только исторический benchmark, не локальный эффект. Данные должны загружаться из воспроизводимого артефакта/API, без зашитых в компонент цифр.
5. Проверить арифметику и отсутствие использования метки до выбора корзины unit-тестами, а загрузку и чтение результата в браузере E2E. Артефакт хранит входные хеши/версию расчёта и команду воспроизведения.

**Границы.** Ручная метка построена по S2 примерно 10 м, а не по купленному кадру 1 м. `yVq` — прокси воды/EL, не фактический ущерб и не предотвращённые потери. Test/Bolivia уже исследовались, а чипы внутри события зависимы; интервал описательный. Цена и доставка остаются сценарными.

**Приёмка.** 70 чипов в артефакте, все статусы и цены пересчитываются из сохранённых входов; UI не заявляет причинный или полевой эффект. Проверки пройдены.

## 2. Ценность информации зоны в рублях

**Пользователь и действие.** Оператор задаёт цену выезда к объекту и видит для каждой зоны ожидаемую экономию ошибочных решений, её цену и влияние на корзину. Бюджет для экономической корзины следует из положительного чистого выигрыша, а не берётся как доля B.

**Требования и контракт.**

1. Для объекта с экспозицией L=V×q и вероятностью p без снимка выбрать более дешёвое действие: выезд за C_visit или риск пропуска pL. После идеального своевременного снимка ожидаемая стоимость равна p×min(C_visit,L). VOI объекта = min(C_visit,pL) − p×min(C_visit,L), не меньше нуля.
2. Ценность зоны — сумма VOI ещё не покрытых объектов; пересечения не удваивают пользу. Для отдельной зоны показывать VOI, самостоятельную цену и чистую выгоду; для корзины пересчитывать цену с групповой скидкой. Недоступные/опоздавшие продукты имеют нулевую операционную пользу.
3. Экономическую C выбирать точным перебором по всем корзинам: максимальная суммарная VOI минус цена данных, при необходимости с обязательным объектом. Покупать лишь при положительном чистом выигрыше; сумма выбранной корзины — выведенный бюджет. Сохранить существующий бюджетный C и явный переключатель метода, чтобы сравнение по ТЗ не ломалось.
4. В интерфейсе дать понятный ввод C_visit, единицы ₽, расчёт на объекте/зоне, итог корзины и причину отказа. API/ZIP помечают все цены ошибок и идеальность снимка как сценарные, рядом с `other_cost_rub`; разные сценарии не выдаются за факты.
5. Проверить граничные p=0/1, пустые/неоценённые объекты, пересечения, скидки, срок и сквозной браузерный путь. Пользователь может вернуться к бюджетному плану без потери настроек.

**Границы.** VOI считает снижение ожидаемых затрат на решение о выезде, не ущерба от паводка. Реальные выезды, чувствительность 1 м снимка, облачность, задержки и V/q должны быть проверены в пилоте.

**Приёмка.** Каждый показанный рубль воспроизводим из p, V, q и сценарных затрат; выбранная корзина глобально оптимальна по этой формуле, а фронтенд позволяет понять и изменить решение.

## Полученный результат

- Backtest: 70 чипов, 571/700 объектов с валидной ручной меткой. При фиксированных 6 500 ₽ и 8 ч сумма ошибки `|pVq−yVq|` сократилась на **60,13%** у C против A; 95% описательный интервал bootstrap по чипам **50,44–69,36%**. Стоимость C — **17,16%** B; исправлено 19 статусов воды/суши из 29, которые исправила бы B. B — контрфактический широкий заказ и может превышать лимит. Числа пересоздаются командой `backend/.venv/bin/python scripts/backtest_procurement.py`; API `/api/backtest`, артефакт `data/backtest/procurement_70.json`.
- Для пересчёта скрипту нужны скачанные официальные S1Hand и сохранённые `.npz` из замороженного аудита `ml/research/audit_20260926/README.md`; эти большие входы в Git не входят. Артефакт хранит SHA256 каждого S1 и прогноза и SHA256 протокола. Чистый checkout сначала воспроизводит аудит в отдельной копии зафиксированного коммита, затем запускает backtest.
- Ценность информации: для Нигерии при цене выезда **10 000 ₽** и сроке 8 ч точный перебор выбирает 4 зоны. Польза **47 092,26 ₽**, цена данных/выведенный бюджет **8 013,24 ₽**, чистая польза после данных **39 079,02 ₽**. При цене выезда 0 ₽ корзина пуста. API `/api/voi` и `/api/voi/export` отдают объектные/зональные расчёты, смету и сценарные допущения. Основной экспорт по ТЗ остаётся отдельным бюджетным A/B/C; экономический режим скачивается своей кнопкой.
- Проверки: 118 backend unit/integration тестов прошли; frontend production build прошёл; целевые E2E backtest и экономического режима на десктопе и узком экране прошли. Общий E2E прогон: 8/10; два существующих SkyFi сценария ожидали галерею после запроса архива, на который внешний каталог вернул пустую выборку. Они не проверяют новые режимы.

До полевого подтверждения остаются фактическая цена и срок поставщика, облачность/качество кадра 1 м, реальные V/q, цена выезда и фактический ущерб. Ретроспектива использует известные test/Bolivia и метку S2 около 10 м; bootstrap по чипам внутри событий не даёт независимого доверительного интервала для нового события.
